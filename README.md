# YouTube TEST для OpenWrt 24.10 / 25.12

Скрипт подготовлен по реальным файлам Podkop, upstream Zapret2 и пакета Routerich. Локальные проверки выполнены; на физическом роутере этот экземпляр скрипта не запускался. Поддержка конкретной установки определяется проверками до изменений, а не только номером OpenWrt.

## Запуск через wget в SSH-терминале роутера

```sh
(umask 077; d=$(mktemp -d /tmp/youtube-download.XXXXXX) || exit 1; trap 'rm -f "$d/run.sh"; rmdir "$d"' EXIT; wget -O "$d/run.sh" https://raw.githubusercontent.com/TMN88/zapret2_strategy_podbor_script/main/youtube-test.sh && YT_FOLLOW=1 sh "$d/run.sh")
```

Команда скачивает файл во временный закрытый каталог, запускает только после успешного скачивания и показывает цветной журнал до результата. Рабочий процесс остаётся в фоне, если SSH отключится. Нужны `wget` с HTTPS и рабочие сертификаты CA; проверка сертификатов не отключается. Запускать от root в SSH-сеансе по LAN/Tailscale. Доступ на роутер и его версия проверяются перед изменениями.

Отдельная программа `nohup` не требуется: фоновый запуск использует `setsid`, рабочий и защитный процессы явно игнорируют SIGHUP средствами shell. Неиспользуемый `timeout` также не требуется; ограничение времени обеспечивает защитный процесс.

Состояние Podkop определяется по наличию процесса `sing-box` и таблицы `inet PodkopTable`. Команда `/etc/init.d/podkop running` не используется: стартовый процесс Podkop может завершиться после настройки sing-box. При отсутствии одного из двух признаков скрипт выводит конкретную причину и останавливается до изменений. Эти признаки подтверждают наличие компонентов обработки трафика, но сами по себе не доказывают доступность VPN или внешних сайтов.

При нескольких секциях Podkop добавьте `PODKOP_SECTION=main` перед `YT_FOLLOW=1`, заменив `main` настоящим именем. Ошибка `Unreviewed ... version` означает несовпадение с изученными файлами Routerich; обходить эту проверку не следует.

## Альтернатива: одна команда из PowerShell

Сохраните `Run-YouTubeTest.ps1` и `youtube-test.sh` в одну папку. Откройте PowerShell в этой папке и выполните, заменив адрес своим:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Run-YouTubeTest.ps1 -Router 192.168.1.1
```

Используйте LAN через `br-lan` или SSH по Tailscale. Ключи, проверка SSH-сервера и пароль используются обычные; скрипт их не сохраняет. Не меняйте настройки в LuCI и не запускайте параллельно Blockcheck во время работы. Закрытие терминала не прерывает фоновую задачу и её защитный процесс.

Если в Podkop несколько секций, добавьте к той же команде `-Section main`, указав настоящее имя нужной секции. При неоднозначности скрипт остановится до изменений. В других секциях списки не изменяются.

Результат появляется в терминале: зелёный — успешная проверка, красный — ошибка, жёлтый — восстановление, голубой — запуск. Возможности отображения ANSI зависят от терминала. Файлы `status` содержат обычный текст без цветов.

## Что выполняется

1. Проверка OpenWrt, необходимых программ, текущего доступа, свободного места, состояния Podkop, отсутствия параллельного Blockcheck и несохранённых UCI-правок. Пакеты и прошивка не устанавливаются и не обновляются.
2. Проверка SHA256 двух изученных файлов Routerich `1.0.5.2-r15`: `blockcheck2.sh` и `init.d/openwrt/uci2config`. Другой вариант отвергается до изменений. Проверяется пригодность curl для HTTP3 и управления версиями TLS. curl из старого лога без HTTP3 проверку не пройдёт.
3. Резервное копирование `/etc/config/podkop`, `zapret2`, существующих `dhcp`, `sing-box`, а также `/opt/zapret2/config`. Каталог резервных копий закрыт от других пользователей. Запоминается исходное состояние Zapret2.
4. Ровно восемь community lists в выбранной секции: `geoblock block porn meta tiktok telegram cloudflare google_play`. Это Geo Block, Block, Porn, Meta, Tik-Tok, Telegram, Cloudflare, Google Play со скриншота. Russia Inside и YouTube среди них отсутствуют. Остальные параметры секции сохраняются. Podkop перезапускается для применения списков.
5. Остановка Zapret2, проверка отсутствия оставшегося `nfqws2`. Проверка назначения YouTube на очевидный FakeIP/частный адрес и маршрута на VPN. SSH-маршрут сравнивается до/после изменений. Процессы Tailscale, сеть, WAN/WAN6 и общие правила firewall скрипт не перезапускает.
6. Три отдельных прохода для `youtube.com`, IPv4: TLS 1.2, TLS 1.3, HTTP3/QUIC. Каждый — `REPEATS=3`, `PARALLEL=0`, `SCANLEVEL=force`, до пяти успешных стратегий. Лимит реализован в частной копии изученного Blockcheck через нормальную процедуру очистки upstream. Установленный файл не изменяется. Протокол с нулём подходящих TCP-результатов не подменяется результатами QUIC. Отсутствие успешного QUIC тоже останавливает транзакцию.
7. Безопасное подмножество TCP-кандидатов (`tcpseg`, простой `multisplit`, `multidisorder`, `oob`) повторно проверяется в режиме `TEST=custom` на TLS 1.2 и TLS 1.3. Принимаются только строки с тремя успешными попытками и итоговым `AVAILABLE`. Внешние blobs, произвольный Lua, параметры процессов и shell-конструкции автоматически не переносятся.
8. Из пересечения прошедших обе проверки выбирается вариант: сначала `tcpseg`, затем `multisplit`, затем `multidisorder`, затем `oob`; при равенстве — более короткая строка, затем лексический порядок. Это прозрачное правило выбора среди протестированных кандидатов, а не измерение скорости или доказательство универсально лучшей стратегии.
9. Создаётся секция `strategy 'TEST'`: включена, порт `443`, L3 `ipv4`, протокол `tcp`, L7 `tls`, hostlist `list_hosts_youtube`, `autohostlist=0`. IP-списки и исключения отсутствуют. Если отдельного непустого youtube-списка нет, скрипт останавливается; глобальный профиль вместо него не создаётся. Существующий TEST не перезаписывается.
10. Все остальные UCI-секции типа `strategy` выключаются без удаления. TEST перемещается на первое место. `main.enabled=1`, глобальный TCP-перехват `main.nfqws_ports_tcp=443`; `main.custom_scripts=0`, чтобы дополнительные пользовательские скрипты не запускали обход параллельно TEST.
11. Проверяется генерация конфигурации, Zapret2 перезапускается, проверяется его состояние, наличие TEST и отсутствие других включённых UCI-стратегий. Выполняются по три настоящих HTTPS HEAD-запроса к YouTube с принудительными TLS 1.2 и TLS 1.3. Лишь после `6/6` и проверки Podkop/маршрута выводится зелёный SUCCESS.

## Почему лимит отличается от одной кнопки LuCI

В изученном `blockcheck.js` автосбор — JavaScript и генерируемый shell-wrapper, а не UCI-опция или CLI `--autocollect`. Он останавливает весь процесс после пяти успешных тестов домена, в том числе повторяющихся вариантов. При одновременно отмеченных TLS1.2/TLS1.3/QUIC все пять могут накопиться на TLS1.2. Тогда остальные протоколы вообще не будут проверены.

Чтобы выполнить требование проверить все три протокола, здесь лимит **5 на каждый отдельный протокол**: до 15 успешных находок в исходных проходах. Дополнительная перепроверка TCP-кандидатов проходит без этого лимита. Это намеренное отличие, а не притворное наличие несуществующего API. Общее число запросов больше пяти: для каждой стратегии выполняются три попытки, плюс базовые и диагностические запросы.

Создание профиля полностью автоматизировано через подтверждённую UCI-схему. Автоматический перенос любых произвольных результатов Blockcheck не поддерживается: если безопасного совместимого варианта нет, выполняется откат и сохраняются логи для ручного анализа.

## Восстановление и границы проверки

При ошибке, сигнале завершения, исчезновении рабочего процесса, истечении двух часов или опасном уменьшении свободного места отдельный защитный процесс запускает восстановление. Он завершает только записанную группу тестовых процессов и удаляет только её таблицу `inet blockcheck<PID>`, затем восстанавливает сохранённые конфигурации, перезапускает Podkop и возвращает Zapret2 в исходное работающее/остановленное состояние. Общего `killall nfqws2` и очистки firewall нет. При сбое самого восстановления статус — `RECOVERY_FAILED`, сохраняются данные для повторной попытки.

Папка запуска: `/root/youtube-test/run-ДАТА-ВРЕМЯ-PID`. Там находятся `run.log`, `status`, `recovery.log`, журналы трёх протоколов, `verify.log`, `ranking.tsv`, `winner.txt`, `final-probe.log`, резервные копии. Эти файлы могут содержать секреты Podkop; не публикуйте их целиком. Скачивайте только нужные диагностические фрагменты. Журналы лежат на постоянном хранилище; после принятия результата их можно удалить вручную вместе с резервной копией.

Для ручного отката после успешного запуска, подставив точный каталог:

```sh
sh /root/youtube-test/run-ДАТА-ВРЕМЯ-PID/run.sh --rollback /root/youtube-test/run-ДАТА-ВРЕМЯ-PID
```

Защита не даёт абсолютной гарантии сохранения удалённого доступа: Podkop меняет маршрутизацию/DNS своими штатными действиями; возможны внешние правила маршрутизации, питание, перезагрузка, ошибки флеш-памяти. Изменения выполняются на уже настроенном работающем Podkop. После перезагрузки watchdog не возобновляется автоматически. При сомнениях запускайте с локальным доступом. Проверка маршрута не доказывает отсутствие всех возможных перенаправлений через nftables или сторонние прокси.

Итоговые `6/6` подтверждают HTTPS с роутера. Это не проверка воспроизведения видео с LAN-клиента. QUIC проверяется на этапе подбора, но итоговый TEST — **только TCP/TLS**, а остальные стратегии, включая UDP/QUIC, по запросу выключены. Работу HTTP3 в итоговой конфигурации скрипт не обещает. Домены googlevideo и поведение браузера требуют отдельной проверки с клиента.

## Проверено локально

- Синтаксис shell в BusyBox ash и синтаксис PowerShell.
- Инструментирование частной копии реального `blockcheck2.sh`: остановка ровно после пятого успеха с вызовом очистки.
- Парсер отвергает результаты 2/3, неуспешные прогоны, IPv6, посторонний домен и базовый успех без стратегии.
- Фильтр кандидатов отвергает shell-инъекции, QUIC и лишние параметры; победитель должен присутствовать в результатах обеих версий TLS.
- На файловых заглушках проверены восстановление резервных копий, возврат исходного работающего/остановленного состояния Zapret2, повторное восстановление и сохранение статуса ошибки восстановления.

Полный прогон OpenWrt/procd/nftables и проверки реального DPI здесь не выполнены: доступа к клиентскому роутеру в этой задаче нет. Неизученные версии намеренно отвергаются; совместимость всех сборок 24.10/25.12 не заявляется.
